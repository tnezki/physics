PHYSICS FORMATIVE ASSESSMENTS — PORTABLE MEMORY / GOLD STANDARD — v2
=====================================================================

PURPOSE
-------
This is the Physics-specific workflow for rebuilding formative assessments. The formative assessments themselves are the authoritative source question bank for downstream summative assessments, practice sets, CYUs, and activities. Therefore question quality is an upstream requirement, not a cleanup step.

SOURCE ORDER
------------
1. This Physics portable memory.
2. Current explicit user instructions.
3. Current unit assessment plan — the formative assessment idea description and timing are the contract.
4. Current unit student/teacher notes and source-grounded textbook material.
5. Current approved/rebuilt Physics formative files.
6. Current Physics formative.css.
7. Authoritative graph_tool.py only when an actual supported quantitative/data graph is needed.

Discarded formative, summative, practice-set, or activity files are NOT content authority. Do not recycle their prompts merely because they already exist.

ASSESSMENT PLAN = CONTRACT
--------------------------
For each formative slot, read its exact assessment-plan description before writing questions. Build what that description says students should do.

Examples:
- "Wave Feature Diagram Labeling" means students label wave features on diagrams. Do not replace it with an energy explanation or misconception critique.
- "Transverse or Longitudinal?" means students classify examples/sketches by wave type. Do not inflate it into an extended explanation task.
- If the plan says DOK 1, keep the cognitive demand at DOK 1 even if a longer explanation would be easy to add.

VERSION STRUCTURE — 8 VERSIONS
-------------------------------
Every formative HTML contains exactly eight versions.

V1–V4 — ASSESSMENT-DAY PARALLEL FORMS
- Same target and DOK.
- Same broad assessment family.
- Genuinely different student-facing tasks.
- May vary representation, layout, scenario, direction of matching, data, vocabulary direction, diagram geometry, and prompt wording.
- Parallel does NOT mean identical shell with letters/numbers/rows shuffled.

V5–V6 — FIRST REASSESSMENT / MAKEUP PAIR
- Same target and DOK as V1–V4.
- Fresh question structure/family.
- V5 and V6 parallel each other but are still distinct.

V7–V8 — SECOND REASSESSMENT / MAKEUP PAIR
- Same target and DOK.
- Another fresh family, different from both V1–V4 and V5–V6.
- V7 and V8 parallel each other but are distinct.

HARD PARALLEL-FORM DIVERSITY RULE
---------------------------------
A version FAILS if a student could reasonably say, "This is the same question with the labels/numbers/order changed."

Changing only any of the following is NOT sufficient:
- A/B/C/D marker letters,
- numerical values,
- row order,
- scenario nouns while preserving identical sentence shell,
- answer order,
- color,
- diagram scale with the same callout pattern.

For V1–V4, intentionally vary at least TWO meaningful student-facing dimensions across the group, such as:
- representation type (diagram / table / scenario / card sort / direct match),
- prompt direction (term→feature vs feature→term),
- diagram organization (single model / split models / numbered callouts / direct labeling),
- context,
- sentence structure,
- response structure.

The four forms must remain comparable in target and approximate difficulty.

PARALLEL-FORM QA — REQUIRED
---------------------------
Before approval, make a version-comparison table for each formative:
Version | representation | prompt structure | response structure | context/values

Then compare V1 vs V2, V1 vs V3, V1 vs V4, V2 vs V3, V2 vs V4, V3 vs V4.
FAIL if any pair is merely a shuffle/renaming/number swap.

Also compare V5–V6 to the V1–V4 family and V7–V8 to both earlier families. They must be structurally fresh.

DOK AUTHENTICITY
----------------
DOK 1:
- recall, recognition, labeling, identification, classification, simple matching.
- a brief factual statement may be included only when the assessment-plan description explicitly calls for one.
- do not add strategic critique, multi-representation reasoning, or explanation chains just to make a question longer.

DOK 2:
- familiar application, calculation, table/data use, graph/diagram interpretation, ranking, completing familiar models.

DOK 3:
- strategic reasoning, misconception correction, representation connection, critique, explanation/defense.

DOK 4:
- extended modeling, design, competing explanations, unfamiliar transfer, evidence-based defense/critique appropriate to the intended formative time.

Do not inflate DOK by mechanically adding "explain."

FIGURE ANSWER-SAFETY — HARD RULE
--------------------------------
A figure may provide evidence but must never reveal the response students are supposed to identify, label, classify, critique, or infer.

Examples:
- Labeling crest/trough/amplitude/wavelength: the image must NOT contain those words at the target locations.
- Classifying transverse/longitudinal: the image may show wave-travel and particle-motion arrows, but may NOT name the wave type.
- Identifying constructive/destructive interference: the image/title/caption may NOT state the interaction type.
- A free-body/force labeling figure must not include the labels students are being asked to supply.

Neutral markers such as A–E, 1–7, X, blank callout lines, brackets, or highlighted regions are allowed.

VISUAL EVIDENCE CHECK — EVERY VISUAL QUESTION
---------------------------------------------
Before accepting a question, answer privately:
1. What can the student directly observe from this representation?
2. What can only be calculated or inferred?
3. Does the prompt claim something the axes/diagram do not establish?
4. Does a title, legend, caption, callout, alt/aria text, or annotation reveal the answer?
5. Does the picture/data agree with the expected answer?

Example failure: a displacement-vs-position wave snapshot does not directly show frequency. Do not state that two curves have different frequencies unless additional time/speed evidence makes that inference valid.

GRAPH VS PHYSICS DIAGRAM
------------------------
GRAPH = quantitative/data/axis representation such as position-time, frequency-response, bar chart, scatter plot, or another supported graph-tool representation.

PHYSICS DIAGRAM = schematic/model such as an unlabeled transverse wave, longitudinal particle model, motion arrows, apparatus, force model, circuit, ray model, or wave interaction sketch.

Use graph_tool.py only for genuine supported graphs. Never force a Physics schematic through a graph function just to use the tool.

For answer-neutral formative schematics, clean inline SVG is preferred when appropriate. If the user requires figures/ to remain empty, inline SVG is especially useful.

GRAPH TOOL RULE
---------------
When a graph is genuinely needed:
1. Copy the authoritative graph_tool.py byte-for-byte as generate_graphs.py.
2. Append generation code only after the complete original source/final permitted append location.
3. Never modify/refactor/restyle the source.
4. Run the script during QA.
5. Verify every referenced graph is generated.
6. Visually inspect representative graphs and confirm they do not reveal answers.
7. Remove generated PNGs before packaging when local generation is expected.
8. Keep generate_graphs.py and the empty figures/ folder.

HTML / CSS
----------
Physics formative HTML uses external teacher-only CSS:
<link rel="stylesheet" href="../../css/formative.css"/>

Use body class="unit-N".
Do not embed duplicate CSS unless explicitly requested.
MathJax configuration must precede the CDN script and include processEscapes:true.

Each version is one <section class="page"> with:
- header-row,
- assessment-title,
- name-line,
- directions,
- task.

One formative file contains V1–V8.

FORMATIVE CSS
-------------
formative.css is standalone and print-oriented. Physics-specific additions may be made when a genuine recurring layout need appears. Do not use CSS to encode answers. Keep inline-SVG support for answer-neutral diagrams.

QUESTION WORDING
----------------
Questions should not sound like a Mad Lib.

Across suitable question sets, vary structure roughly:
- one-third standard/givens-first,
- one-third inverted/action-or-agent-first,
- one-third context-rich real-world wording.

Rotate vocabulary directions:
- term → definition,
- definition → term,
- concept → term,
- term → concept.

This is a variation target, not a reason to make an unnatural sentence.

MULTISTEP RULE
--------------
A genuine multistep problem normally requires determining an intermediate quantity needed to obtain one final requested answer.

Good examples:
- determine container volume, then use it to determine density;
- determine a constant speed from one trip, then use it to determine travel time for a second trip;
- determine Celsius temperature change, then convert that change to Fahrenheit.

Not enough: use two formulas and report two unrelated answers.

FORMATIVE ASSESSMENTS ARE THE BANK
----------------------------------
Do NOT create a separate practice-set question bank first.

Once the formative family is approved, its eight versions are the source bank for downstream work. Practice sets, CYUs, summative questions, and activities should be adaptations of the formative families:
- reword,
- rearrange,
- change values,
- change context,
- vary representation,
- combine closely related source ideas when appropriate,
while preserving the target, true DOK, formula limits, misconception, and representation skill.

DOWNSTREAM PRACTICE-SET RULE
----------------------------
The four Physics practice sets must be genuinely different parallel sets, not identical copies under different filenames. When adapting a formative family across practice forms, vary actual prompts, contexts, values, representations, and ordering where appropriate. QA must compare forms and fail exact or near-identical sequences.

QUESTION/ANSWER VALIDATION — REQUIRED
-------------------------------------
For every version, privately record/check:
- intended answer or scoring idea,
- all information needed is present,
- no hidden assumption is required,
- terminology is precise,
- formula is within the unit assessment-plan limit,
- arithmetic/units are correct when quantitative,
- diagram/data supports the prompt,
- answer is not visible in the figure,
- DOK matches the required thinking.

FORMATIVE FAMILY QA
-------------------
Every formative must pass:
1. Assessment-plan alignment and timing.
2. DOK authenticity.
3. V1–V4 meaningful parallel-form diversity.
4. V5–V6 fresh family.
5. V7–V8 another fresh family.
6. Physics answer is unambiguous and source-supported.
7. All necessary information is supplied.
8. Formula/symbol limits respected.
9. Representation agrees with prompt and expected answer.
10. No answer-revealing labels/annotations/titles/alt text.
11. Expected answer checked for every version.
12. Natural wording; no repetitive template shell.
13. HTML/CSS/MathJax/print structure validated.
14. Pairwise version comparison performed; no near-duplicate forms.

UNIT 5 DOK 1 PILOT 2 — GOLD-STANDARD INTERPRETATION
---------------------------------------------------
DOK 1.1 — Wave Feature Diagram Labeling
- V1–V4: same labeling target but different student-facing representations: neutral callouts, numbered leaders, mixed models, split model layout.
- V5–V6: highlighted-feature recognition family.
- V7–V8: direct labeling family where students place labels/arrows themselves.
- Never print target feature names at their diagram locations.

DOK 1.2 — Transverse or Longitudinal?
- V1–V4: motion-arrow panels, scenario cards, mixed visual/verbal evidence, and direction-data table.
- V5–V6: card-sort family.
- V7–V8: determine type from evidence / insufficient-information family.
- Classification options may include transverse, longitudinal, both, or not enough information as the plan specifies.

DOK 1.3 — Sound Needs a Medium
- V1–V4: can/cannot travel, source-medium-receiver, environment sort, and medium-type table.
- V5–V6: identify the medium in concrete sound scenarios.
- V7–V8: mechanical-wave/path recognition.
- Solids, liquids, and gases can act as sound media; an ideal vacuum cannot.

DOK 1.4 — Wave Phenomenon Snapshot Sort
- V1–V4: scenario table, neutral picture snapshots, inverse match, clue cards.
- V5–V6: definition-to-term family.
- V7–V8: discriminate commonly confused phenomenon pairs.
- Target terms: reflection, refraction, resonance, interference, Doppler effect, beats.
