PHYSICS UNIT REVIEW BUILD — PORTABLE MEMORY / GOLD STANDARD
================================================================

PURPOSE
-------
THIS FILE IS THE CURRENT SINGLE SOURCE OF TRUTH FOR PHYSICS UNIT REVIEW BUILDS.

The approved Unit 1 review package is the gold-standard interpretation for:
  • one consolidated review guide per unit
  • one linked student practice document per unit
  • section-first organization with DOK information layered into the review
  • unit-wide vocabulary and formulas/relationships
  • concise bulleted summaries
  • Learning Targets and I-can statements
  • source-grounded figures/models
  • misconception warnings
  • final unit-wide DOK map
  • final readiness checklist
  • shared external review.css
  • shared external base.css + practice_set.css for the practice document
  • a floating Back-to-Top button on the main review
  • a pill-style Practice Problems link in the main top navigation
  • Notability-friendly open-response practice with 50 px workspaces
  • one top-level reviewN/ folder in the final ZIP
  • QA and packaging rules

"BUILD," "CREATE," "MAKE," "GENERATE," OR "REBUILD" MEANS COMPLETE THE FULL PACKAGE.
A plan, outline, partial HTML, or list of review topics is not a completed build.

================================================================
CORE REVIEW PHILOSOPHY — LOCKED DEFAULT
================================================================

The MAIN REVIEW is SECTION-FIRST.

Students normally remember content by where it was learned (for example, equilibrium or
net force), so the main organizational spine is the unit's section sequence.

DOK is SECONDARY / DIAGNOSTIC.

DOK information belongs INSIDE the review as a way to communicate increasing depth of
thinking, but students should not have to navigate the whole review as separate DOK 1,
DOK 2, DOK 3, and DOK 4 chapters.

The approved hybrid architecture is:

  1. Hero / title / top navigation
  2. Unit at a Glance
  3. Unit-wide Vocabulary
  4. Unit-wide Formulas / Relationships
  5. Section-by-section Review
  6. Unit-wide DOK Map
  7. Final Check / Before the Summative

This is the locked default unless the user explicitly changes it.

----------------------------------------------------------------
UNIT AT A GLANCE
----------------------------------------------------------------

Purpose:
  • give students the conceptual story of the unit before details
  • show how major concepts connect
  • communicate the big-picture learning goal

Good content:
  • concise introductory paragraph
  • concept chain / flow
  • one unit-level standard/target card when useful

Do not turn this into a long chapter summary.

----------------------------------------------------------------
UNIT-WIDE VOCABULARY
----------------------------------------------------------------

Include the important vocabulary students are expected to recognize/use across the unit.

Preferred design:
  • grouped vocabulary cards/chips
  • groups may follow sections or conceptual families
  • list terms, not paragraphs of definitions, unless the user asks for definitions

Section-specific vocabulary may be repeated later in a smaller "Key terms" strip.
The full bank should appear once near the top so students can scan the unit quickly.

Only include terms supported by the assessment plan/notes/current assessments.

----------------------------------------------------------------
UNIT-WIDE FORMULAS / RELATIONSHIPS
----------------------------------------------------------------

Include every formula or symbolic relationship students are expected to use in the unit.

For each relationship, prefer:
  • short name/label
  • formula
  • one concise explanation of what it means / when it applies

HARD RULE:
State CONDITIONS / LIMITATIONS when a relationship is only valid in a specific situation.
For example, a support-force relationship should not be presented as universally true if it
only holds for equilibrium on a level surface.

Do not add formulas merely because they are common Physics formulas.
Use the current unit sources as the contract.

----------------------------------------------------------------
SECTION-BY-SECTION REVIEW — MAIN BACKBONE
----------------------------------------------------------------

Each instructional section gets its own review panel.

Required section components:
  • section number and title
  • Learning Target
  • all current I-can statements
  • concise bulleted summary
  • useful source-grounded figure/model when it improves understanding
  • section-specific key vocabulary strip
  • compact DOK ladder / what students should be able to do
  • common misconceptions / traps when supported by the unit sources

The section heading should preserve the assessment-plan section title exactly or nearly
exactly. Do not casually rename sections.

Recommended internal flow:

  Section head
  → Learning Target
  → I-can checklist
  → Bulleted Summary
  → Figure/model
  → Key vocabulary
  → DOK strip
  → Common misconceptions

Commented structural skeleton:

----------------------------------------------------------------
BULLETED SUMMARY STANDARD
----------------------------------------------------------------

Summaries should be:
  • bulleted
  • concise
  • source-grounded
  • written for student review, not teacher commentary
  • focused on relationships, distinctions, and reasoning students must remember

Avoid giant prose blocks.
Avoid simply copying the notes word-for-word.
Avoid adding motivational filler.

----------------------------------------------------------------
DOK INSIDE THE REVIEW
----------------------------------------------------------------

The review page may show compact DOK cards inside each section and a larger unit-wide DOK
map near the end.

Purpose:
  • tell students what increasing depth of thinking looks like
  • help them distinguish recall from application and strategic reasoning
  • NOT to reorganize the entire unit away from its section sequence

Typical progression:
  • DOK 1 — Recognize / recall / identify
  • DOK 2 — Apply / calculate / interpret / compare
  • DOK 3 — Reason / diagnose / critique / connect representations
  • DOK 4 — Synthesize / design / defend / extended modeling WHEN the unit sources support it

HARD RULE:
Do not invent unsupported DOK expectations merely to fill four boxes.
If the assessment plan does not meaningfully support a DOK level, omit it or clearly treat
it as an extension rather than pretending it is a normal assessed expectation.

DOK descriptions should name concrete unit-specific tasks, not generic definitions.

----------------------------------------------------------------
COMMON MISCONCEPTIONS / TRAPS
----------------------------------------------------------------

Include concise misconception cards when they are supported by notes/assessments.

Good examples:
  • confusing a property with a force
  • confusing an individual force with net force
  • assuming motion requires a continuing force
  • applying a formula outside its valid condition
  • reading an arrow/model incorrectly

These are STUDY-GUIDE warnings, so they may explicitly state the correct idea.
They are not assessment questions.

----------------------------------------------------------------
UNIT-WIDE DOK MAP
----------------------------------------------------------------

Near the end, include a unit-wide DOK map that reorganizes the entire unit by depth of
thinking while preserving the main section-first organization elsewhere.

This is a secondary lens, not the primary navigation.

Use concrete unit content in each DOK card.

----------------------------------------------------------------
FINAL CHECK / BEFORE THE SUMMATIVE
----------------------------------------------------------------

End with a compact readiness checklist.

Recommended categories:
  • Vocabulary & Concepts
  • Representations & Calculations
  • Reasoning

Checklist items should be short, action-oriented, and source-grounded.

Do NOT turn Final Check into another full assessment.

================================================================
FLOATING BACK-TO-TOP BUTTON — HARD RULE
================================================================

The main review page includes a clearly visible floating button on the right/bottom:

  <a class="floating-top" href="#top" aria-label="Back to top" title="Back to top">↑ Top</a>

Requirements:
  • fixed to lower-right on normal screen layout
  • visually distinct from body text
  • links to hero id="top"
  • does not cover important content unnecessarily
  • hidden in print

The shared review.css MUST provide the styling.

  @media print {

================================================================
REVIEW VISUALS / IMAGES / GRAPHS
================================================================

REVIEW VISUAL PHILOSOPHY
------------------------
The main review is instructional, not an assessment.

Therefore review visuals MAY be labeled and explanatory when that helps students study.
They do NOT need the same answer-neutral restrictions as an exit ticket.

Preferred source order for visuals:
  1. useful figures already present in the approved unit notes
  2. useful figures already present in approved assessment/practice resources
  3. locally generated graph-tool figures for true quantitative/data graphs
  4. clean locally generated Physics diagrams/images when genuinely useful

Do not add a visual merely to fill space.
Do not impose a fixed figure quota.

When using existing source images:
  • copy only the images actually used into reviewN/figures/
  • give them stable descriptive names when practical
  • use useful alt text
  • do not include unused images from the source ZIPs

TRUE QUANTITATIVE GRAPHS / graph_tool.py
----------------------------------------
Use the authoritative graph_tool.py for true quantitative/data/axis graphs when supported.

If a graph is needed:
  1. Read graph_tool.py completely.
  2. Confirm an existing graph type fits.
  3. Copy the authoritative file byte-for-byte as:

       reviewN/generate_graphs.py

  4. Append generation blocks only below the final permitted append marker.
  5. Never edit the authoritative source above that marker.
  6. Run the generator during QA.
  7. Inspect the generated graph visually.
  8. Put only used output files in reviewN/figures/.

If no true graph is needed, do NOT force generate_graphs.py into the ZIP.

PRACTICE-PAGE VISUAL SAFETY
---------------------------
Unlike the main review, a figure used as part of a student practice QUESTION must not reveal
the response students are supposed to identify, calculate, classify, or infer.

================================================================
STUDENT PRACTICE PAGE — LOCKED DEFAULT
================================================================

FILE:
  review_N_practice.html

PURPOSE:
A simple, downloadable, Notability-friendly practice document.
It is NOT another review guide.

The practice page should feel like the user's regular Physics practice sets.

HARD RULES:
  • open-response only
  • NO multiple choice
  • NO DOK labels shown to students
  • NO I-can tags shown to students
  • NO focus statements
  • NO hints
  • NO commentary
  • NO diagnostic advice
  • NO "best study move" text
  • NO extra navigation buttons/menus
  • NO separate "Section 1.1" line above the section title
  • exactly one simple section heading line such as:

      1.1 Thinking Like a Physicist

  • blank workspace after EVERY question
  • default workspace = exactly 50 px

The practice page is organized by SECTION, not by DOK.

----------------------------------------------------------------
PRACTICE CSS — SHARED EXTERNAL DEPENDENCIES
----------------------------------------------------------------

The practice HTML links EXACTLY to:

  ../../css/base.css
  ../../css/practice_set.css

with base.css loaded FIRST.

Do NOT bundle either CSS file inside reviewN.zip.
Do NOT create a separate review-practice stylesheet when practice_set.css already provides
what is needed.

The approved workspace structure is:

  <div class="workspace ws-50"></div>

The shared practice_set.css provides ws-N utility classes.
At the current approved version, workspace heights include:
  • ws-10 through ws-960 in 10 px increments
  • plus ws-25

This means the user can manually increase an individual practice workspace by changing only
the class, for example:

  ws-50  ->  ws-80
  ws-50  ->  ws-120
  ws-50  ->  ws-200

Do not change shared CSS just to enlarge one question's workspace.

================================================================
PRACTICE QUESTION COUNT / BALANCE
================================================================

DEFAULT FOR A NORMAL FIVE-SECTION UNIT:
  approximately 20–25 open-response questions total.

Default section allocation:
  • usually 4 questions per section
  • use 5 when the section has more distinct/substantial targets and an extra question is
    genuinely useful

The goal is not to hit a rigid number.
The goal is to give enough practice for the section target set without rebuilding the entire
practice-set bank.

Unit 1 gold-standard result:
  • 5 sections
  • 4 questions per section
  • 20 questions total
  • 20 workspaces total
  • every workspace ws-50

PRIVATE DOK DESIGN (NOT DISPLAYED ON PRACTICE PAGE)
--------------------------------------------------
The practice bank should still have sensible cognitive balance even though students do not
see DOK labels.

A good default is:
  • a small amount of DOK 1
  • mostly DOK 2
  • a few genuine DOK 3 items
  • no routine DOK 4 unless the user explicitly wants extended synthesis/challenge practice

A rough planning range may be:
  • 15–20% DOK 1
  • 60–70% DOK 2
  • 15–20% DOK 3

These are planning ranges, NOT hard quotas.
Question quality and alignment matter more than exact percentages.

PRACTICE COVERAGE
-----------------
Use the assessment plan/I-cans as the content contract.
For sections with many I-cans, combine related targets intelligently rather than forcing one
question per I-can and bloating the practice document.

Practice questions may be adapted from approved formative/summative/practice questions or
written originally from the I-can statements and notes when needed.

Do not use later-section concepts in an earlier-section practice block.
