PHYSICS SUMMATIVE ASSESSMENT BUILD — PORTABLE MEMORY / GOLD STANDARD
================================================================

PURPOSE
-------
This is the Physics-specific summative workflow. Algebra summative memories may be used for structural ideas only. When they conflict with the Physics assessment plan, approved Physics formative assessments, Physics CSS, or explicit user instructions, this memory wins.

SOURCE PRIORITY
---------------
1. Current explicit user instructions.
2. This Physics summative portable memory.
3. Current unit assessment plan — contract for summative length, DOK balance, section coverage, formula limits, and answer-sheet structure.
4. The rebuilt/approved 16 formative assessment families. Their versions are the canonical question bank for summative construction.
5. Current Physics summative.css.
6. Authoritative graph_tool.py.
7. Algebra summative portable memory only for useful structural reference.

CANONICAL BANK RULE
-------------------
Do not invent a separate summative bank. The 16 formative families are the bank. Summative questions are adaptations of those formative versions: reword, rearrange, swap numbers/contexts, convert open response to multiple choice with misconception-based distractors, or vary representation while preserving concept and intended DOK.

VERSION ARCHITECTURE
--------------------
Use 8 versions unless the current assessment plan or user explicitly says otherwise:
- V1-V4: same-day parallel forms. Same blueprint, genuinely different wording/values/contexts/figures.
- V5-V6: first reassessment/makeup pair. Same standards/DOK blueprint, fresh question families or entry points.
- V7-V8: second reassessment/makeup pair. Fresh again and different from V5-V6.
A student should not be able to use one version as a near-identical answer key for another.

UNIT 5 GOLD-STANDARD TEST STRUCTURE
-----------------------------------
Follow the Unit 5 assessment-plan structure unless later plans explicitly differ:
- 45-minute paper test.
- Q1-Q16 multiple choice.
  * 5 DOK1
  * 6 DOK2
  * 4 DOK3
  * 1 DOK4/evidence-evaluation item where the plan explicitly requires it
- Q17-Q20 free response on the back answer sheet.
- One consolidated HTML with all versions, answer keys, one generic bubble answer sheet, and one FR work page.

PHYSICS CSS
-----------
Use external ../../css/summative.css. Do not copy Algebra inline-CSS architecture into Physics. The CSS is standalone and print-specific. When a compact quantitative graph needs more height than the normal .figure tier, use .figure.figure-tall.

QUESTION QUALITY
----------------
- The assessment-plan description and approved formative family are the contract.
- Figures must never reveal the answer students are asked to identify, label, classify, critique, or infer.
- Before accepting any graph/diagram question, ask: What can actually be observed? What must be calculated? What cannot be determined from this representation?
- Never claim frequency from a position snapshot unless additional time/speed information justifies it.
- Keep formula use inside the unit formula/symbol limit.
- Rotate vocabulary directions: term->definition, definition->term, concept->term, term->concept.
- Vary wording: roughly one-third standard/givens-first, one-third inverted/action-first, one-third context-rich where appropriate.
- Do not sound like a Mad Lib.
- A multistep numerical problem normally requires an intermediate quantity needed to obtain one final answer. Two unrelated calculations with two answers are not a multistep problem.

MULTIPLE-CHOICE DISTRACTORS
---------------------------
Use distractors based on actual misconceptions exposed by the formative families. Avoid absurd distractors. Rotate correct-answer positions across forms.

VISUALS
-------
Use graphs/diagrams when they genuinely assess the target. Graphs are quantitative/data displays; physics diagrams are schematics/models. Do not force diagrams through graph_tool. Inline answer-neutral SVG is appropriate for wave/sound schematics. Use graph_tool for true data graphs.

GRAPH TOOL
----------
Copy graph_tool.py byte-for-byte to generate_graphs.py. Append generation calls only after the complete source/final append marker. Run during QA. Inspect representative outputs. If local generation is the deployment model, remove generated PNGs before packaging and leave figures/ ready for regeneration.

SOURCE TRACEABILITY
-------------------
Include unit[#]_summative_source_map.csv in the ZIP. For each summative target and version family, record source formative family, section, DOK, and adaptation type.

QA — REQUIRED
-------------
1. Version/count: expected number of versions; 20 questions per version for Unit 5; 16 MC + 4 FR.
2. Blueprint: section coverage, DOK counts, formula limits.
3. Parallel-form quality: V1-V4 genuinely distinct; V5-V6 fresh; V7-V8 fresh again.
4. Physics correctness: independently verify every numeric answer and every conceptual key.
5. Representation integrity: figures support the question and do not reveal the answer.
6. Visual generation: graph files generated successfully; representative graphs inspected.
7. HTML/MathJax/CSS: external summative.css, MathJax config before CDN, no control-character corruption.
8. Answer key/sheet: keys match all versions; answer sheet includes all version bubbles and Q1-Q16; FR page has Q17-Q20 quadrants.
9. ZIP: correct top-level folder, HTML, generate_graphs.py when needed, figures/, source map; no temporary outputs.

UNIT 5 LESSONS LEARNED
----------------------
- Do not use a labeled diagram for a labeling question.
- Do not ask students to infer frequency from a displacement-vs-position snapshot when frequency is not supported.
- Do not treat rearranged labels or number swaps as sufficient parallel-form diversity.
- Downstream practice sets and activities depend on these assessment questions, so content quality is more important than bulk generation speed.
