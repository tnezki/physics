PHYSICS PRACTICE SETS BUILD — PORTABLE MEMORY / GOLD STANDARD
================================================================

PURPOSE
-------
This portable memory defines the gold-standard workflow for building PHYSICS practice-set
packages. It is Physics-specific. It replaces Algebra-specific practice-set assumptions
when the two conflict.

The approved Section 1.1 test package is the reference interpretation for naming,
folder/ZIP structure, HTML architecture, visual handling, source adaptation, and QA.

A Physics practice-set package is NOT an assessment copy and is NOT a single worksheet.
It is a five-HTML-file section package built for Notability/endless-page use, with a
planned pool of source-grounded questions, spiral practice, exit tickets, a CYU, graphs,
and Physics diagrams.

================================================================
SOURCE PRIORITY
================================================================

When sources disagree, use this order:

1. THIS Physics portable memory.
2. User's explicit instructions in the current conversation.
3. Physics Teacher Dashboard — authoritative for deployment folder and HTML filenames.
4. Current unit assessment plan.
5. Current unit's 17 assessment files:
     • 16 formative assessments (DOK 1.1–1.4, 2.1–2.4, 3.1–3.4, 4.1–4.4)
     • 1 summative assessment
6. Current approved Physics practice-set package / gold-standard sample, when supplied.
7. practice_set.css and base.css.
8. graph_tool.py.
9. Algebra practice-set samples, only for structural reference if still useful.
10. Saved memory / prior habits.

The Physics Dashboard controls naming. Do NOT use the old Algebra ZIP/folder naming if it
conflicts with the Dashboard.

SOURCE-GROUNDING RULE
---------------------
The question pool may reword, rearrange, combine, vary numbers/contexts, or convert the
format of questions from the assessment plan, formatives, and summative. The goal is
practice, not verbatim duplication of graded assessment items.

Preserve:
- the intended Physics concept,
- the DOK level,
- the learning target,
- the vocabulary meaning,
- the formula/symbol limits,
- the misconception being tested,
- and the representation skill.

Do NOT silently add Physics content that is not supported by the uploaded unit sources.
Do NOT leak unreleased later-section concepts into questions that require students to know
them.

A later-section diagram MAY be used only as a generic representation/model example when the
question itself targets an already-taught skill and does not require unreleased Physics.

TEST-BUILD EXCEPTION
--------------------
If the user explicitly says this is a test and intentionally supplies only the assessment
plan (or another reduced source set), proceed using the supplied sources and clearly treat
questions as source-grounded adaptations rather than claiming they were copied from missing
assessments. Do not invent claims about files that were not supplied.

================================================================
PHYSICS QUESTION-POOL STANDARD
================================================================

Unless the user explicitly changes the counts, build a PRIVATE section question pool with
EXACTLY:

  12 DOK 1 question families
  12 DOK 2 question families
   5 DOK 3 question families
   2 DOK 4 question families
  --------------------------------
  31 unique question families total

These 31 families are the source pool for PS1, PS2, PS3, PS4, and CYU selection.

The four main practice files each contain 16 main problems, so the 31-family pool will be
reused/rearranged/adapted across files. Reuse is expected across different practice sets;
identical cloning within the same file is not.

REUSE RULES
-----------
- A question family may recur in another practice file with different wording, numbers,
  context, evidence, or representation.
- Do not repeat the exact same prompt twice in one HTML file.
- Preserve DOK when rewording.
- Do not inflate a DOK 1 recognition item into DOK 3 merely by adding "explain why."
- Do not reduce a DOK 3/4 model/critique task into simple recall.
- Avoid copying summative wording verbatim when a clean practice adaptation is possible.

INTERNAL PRACTICE IDS
---------------------
Use traceable internal IDs such as:
  U1-S1-DOK1.01
  U1-S1-DOK2.07
  U1-S1-DOK3.03
  U1-S1-DOK4.02

These are PRACTICE-POOL IDs, not claims that an assessment source used the same ID.

Before writing HTML, privately record for all 31 families:
  ID
  DOK
  learning target / skill
  source assessment(s) or plan idea
  question format
  current / mastery / last use
  graph needed? yes/no
  diagram needed? yes/no
  expected answer / scoring idea

================================================================
SPIRAL STRUCTURE — EACH MAIN PRACTICE FILE
================================================================

Each of the four main files has 16 main problems:

  Problems 1–4:   Current — requested section
  Problems 5–12:  Mastery Spiral
  Problems 13–16: Last Section Spiral

Use these section labels exactly:

  Current — Section [UNIT].[SECTION]: [SECTION_NAME]
  Mastery Spiral
  Last Section Spiral

CURRENT
-------
Targets the requested section's learning target, I-can statements, DOK ladder, formulas,
misconceptions, and representations.

LAST SECTION SPIRAL
-------------------
Normally targets the immediately previous section.

For Section 1.1, there is no previous Physics section. Use appropriate prerequisite science,
measurement, evidence, graph-reading, formula-literacy, or general reasoning skills while
retaining the Last Section Spiral label because the page structure is locked.

MASTERy SPIRAL
--------------
Targets older Physics sections/units and prerequisite skills that students should retain.
For early Unit 1, use suitable prerequisite science/math/modeling skills.

Do not use unreleased future content as required knowledge.

================================================================
PRACTICE-SET PROGRESSION
================================================================

PS1 — practice_set_[U]_[S].html
  Most accessible introduction to the section practice.
  Strong DOK 1–2 presence, with a small amount of DOK 3/4 where appropriate.
  Includes Exit Ticket.

PS2 — practice_set_[U]_[S]_2.html
  Activity / second practice set.
  Similar skills with different arrangements, representations, numbers, and contexts.
  Includes Exit Ticket.

PS3 — practice_set_[U]_[S]_3.html
  Third parallel practice set.
  Continue variation; do not make it a clone of PS1 or PS2.
  Includes Exit Ticket.

PS4 — extra_practice_[U]_[S].html
  Extra Practice.
  May carry a somewhat stronger DOK 2–4 mix while still containing accessible work.
  NO Exit Ticket.

Do not force the exact same DOK count in every practice file. The hard DOK count applies to
the 31-family source pool. Across placements, keep a sensible progression and do not let
DOK 4 dominate a short practice set.

================================================================
EXIT TICKETS — PS1, PS2, PS3 ONLY
================================================================

After the 16 main problems in PS1, PS2, and PS3, add:

<div class="exit-ticket-label">Exit Ticket</div>
<div class="exit-ticket-grid">
  four short problem cells
</div>
<div class="workspace wu-ws-600"></div>

Exactly four questions:
  Q1 — Current section, DOK 1–2
  Q2 — Current section, DOK 1–2, different format/angle from Q1
  Q3 — Last section / prerequisite spiral, DOK 1–2
  Q4 — Mastery / older prerequisite skill, DOK 1–2

Exit-ticket questions are AI-derived adaptations, not direct assessment copies.
No workspace div goes inside an exit-ticket cell.
All cell text must be wrapped in <p> tags.

PS4 has NO exit ticket.

================================================================
CYU — CHECK YOUR UNDERSTANDING
================================================================

File:
  cyu_[UNIT]_[SECTION].html

Use exactly 6 cells in one .exit-ticket-grid:

  Row 1: 2 Current questions
  Row 2: 2 Last questions
  Row 3: 2 Mastery questions

Select the six most representative/self-contained items from the FINAL PS4 problem set:
- Current: two varied DOK 1–2 items
- Last: two accessible varied items
- Mastery: one accessible item plus one somewhat stronger item when appropriate

Rules:
- exactly 6 problem cells
- NO workspace div inside any CYU cell
- source/practice ID in problem-meta
- all text wrapped in <p> tags
- one <div class="workspace wu-ws-600"></div> AFTER the grid

HTML / CSS — LOCKED STRUCTURE
================================================================

Exactly two external CSS links, in this order:

<link rel="stylesheet" href="../../css/base.css"/>
<link rel="stylesheet" href="../../css/practice_set.css"/>

Never embed a <style> block.

MathJax config comes BEFORE the CDN script:

ENDLESS PAGE RULE
-----------------
Physics practice sets are Notability-first endless-page documents.

Use:
  class="problem"

Never use:
  class="problem half"
  .ps-page wrappers
  break-after page structures

Problems flow naturally one after another. practice_set.css handles break-inside avoidance.

================================================================
VISUAL STANDARD — GRAPHS AND DIAGRAMS ARE DIFFERENT
================================================================

THIS DISTINCTION IS CRITICAL.

A GRAPH is a quantitative/data/coordinate representation such as:
- scatter plot
- line graph
- bar graph
- position-time / velocity-time / force-time style graph
- proportional relationship graph
- blank coordinate/modeling graph
- other axis-based graph supported by graph_tool.py

A PHYSICS DIAGRAM is a model/schematic/visual situation such as:
- force/free-body style diagram
- opposing-force arrows on an object
- support force and weight on a book/person
- hanging-sign tension comparison
- flawed force model to critique
- scenario + motion + force-model comparison
- motion-dot diagram
- vector-arrow diagram
- ray diagram
- circuit schematic
- wave sketch
- field-line model
- apparatus / investigation setup
- dot-grid or dot-paper reasoning figure
- comparison panels showing physical situations

Do NOT call every image a graph.
Do NOT force a force diagram, motion-dot model, circuit schematic, ray diagram, etc. through
a coordinate-graph function merely to say graph_tool.py was used.

GOLD-STANDARD VISUAL QUANTITY
-----------------------------
Unless the user explicitly changes this requirement, each section package should include AT
LEAST:

  5 DISTINCT graph files
  5 DISTINCT Physics diagram files

Count UNIQUE files, not repeated placements in multiple practice HTML files.
Reuse a useful visual across PS1–PS4 when instructionally appropriate.

If a section truly cannot support five meaningful graphs without inventing irrelevant
content, do not create nonsense. Use the strongest source-aligned visuals possible and
state the exception in QA. However, the default target is 5 graphs + 5 diagrams.

================================================================
GRAPH TOOL WORKFLOW — GRAPHS ONLY
================================================================

The uploaded graph_tool.py is authoritative for GENERATED GRAPHS.

1. Read graph_tool.py completely.
2. Identify graph functions that actually fit the needed graph.
3. Copy graph_tool.py in full as:
     generate_graphs.py
4. Do not modify, refactor, restyle, delete, or insert code into the authoritative source.
5. Append graph-generation blocks only after the permitted final append marker.
6. Every top-level appended call starts at column 0.
7. Do not add duplicate imports, OUTPUT_DIR definitions, or style overrides in appended code.
8. Use neutral/non-answer-revealing graph titles.
9. Run generate_graphs.py during QA.
10. Verify every expected graph PNG is produced successfully.
11. Visually inspect representative graphs.
12. Before final ZIP assembly, REMOVE the generated graph PNGs from the delivered figures/
    folder. The user runs generate_graphs.py locally to regenerate them.

----------------------------
Generated graph PNGs are NOT packaged in the final ZIP.
The graph script IS packaged.
The HTML still references the expected graph filenames in figures/.

================================================================
PHYSICS DIAGRAM WORKFLOW — STATIC PNGs
================================================================

Physics diagrams are NOT the same thing as graph-tool graphs.

When the practice problem needs a force diagram, motion-dot diagram, physical comparison,
circuit/ray/field schematic, apparatus picture, dot-paper figure, or similar model:

1. Create a clean static diagram using the available diagram/image-generation workflow.
2. Do NOT modify graph_tool.py to fake a diagram type that it does not support.
3. Do NOT replace a needed Physics diagram with ASCII art.
4. Keep the visual simple, high-contrast, classroom-readable, and textbook-like.
5. Use arrows, labels, object shapes, and panels only as needed for the question.
6. Do not reveal the answer in the title, labels, arrow magnitudes, or annotation unless the
   supplied information is part of the problem.
7. Save as PNG in the package's figures/ folder.
8. STATIC DIAGRAM PNGs STAY in the delivered ZIP.

Approved diagram style examples include:
- Book at Rest on a Table
- Box Moving at Constant Speed
- Flawed Force Diagram: Delivery Cart
- Hanging Sign Comparison
- Opposing Horizontal Forces
- Plant Basket Supported by Two Chains
- Scenario, Motion, and Force Model
- Person Standing Still on a Scale
- Same-Direction Pulls on a Sled

Diagram filenames:
  u[unit]_ps_s[section]_diagram_[descriptor]_v1.png

Examples:
  u1_ps_s1_diagram_opposing_forces_v1.png
  u1_ps_s1_diagram_constant_speed_box_v1.png
  u1_ps_s1_diagram_flawed_cart_v1.png
  u1_ps_s1_diagram_hanging_signs_v1.png
  u1_ps_s1_diagram_representation_mismatch_v1.png

IMPORTANT DELIVERY DISTINCTION
------------------------------
Final figures/ folder may therefore be NON-EMPTY.
It should contain the static Physics diagrams/source images that must ship with the HTML.
It should NOT contain graph PNGs that generate_graphs.py is responsible for producing.

This intentionally OVERRIDES the old Algebra portable-memory statement that figures/ must
always be empty.

================================================================
FIGURE HTML
================================================================

Use:

<div class="ps-figure wu-img-350">
  <img src="figures/[filename].png" alt="[clear accessible description]"/>
</div>

Choose wu-img size based on readability, not habit.
A multi-panel Physics diagram may need 4–6 inches.
A simple graph may work at 3–3.5 inches.

Do not add an image border in HTML; CSS controls image styling.

================================================================
QUESTION / VISUAL DESIGN RULES
================================================================

Visuals must DO WORK. Do not add decorative images merely to hit a count.

Good visual uses:
- read a graph and describe evidence
- identify an outlier
- compare slopes/trends
- use a blank graph as the student's modeling workspace
- critique a flawed force diagram
- identify what a model represents
- compare two physical setups
- connect a scenario, motion description, and diagram
- draw missing arrows/labels
- use a dot diagram to infer motion
- interpret measurement layout or apparatus placement

A DOK 1 question may use a diagram for recognition.
A DOK 2 question may interpret or complete a graph/diagram.
A DOK 3 question may compare representations or critique a model.
A DOK 4 question may design an investigation/model using a provided blank graph or diagram.

Do not use a future-section visual in a way that requires future-section knowledge.

================================================================
PHYSICS WORDING STANDARD
================================================================

Questions should sound like Physics practice, not a Mad-Lib bank.

Use a mix of:
- direct identification
- definition ↔ term
- short scenario
- evidence/data interpretation
- graph interpretation
- diagram interpretation
- model critique
- misconception correction
- formula-as-relationship reasoning
- calculation where the section supports it
- investigation design
- comparison / ranking

Vary sentence structure and contexts.
Do not mechanically append "Explain" to every item.
Do not turn all vocabulary questions into "Which term means...?"

When formulas are used, stay inside the unit assessment-plan formula/symbol limit.
Do not unnecessarily hand students a derived quantity that they should determine.

================================================================
MATCHING / SORTING RULE
================================================================

If a question uses matching:
- shuffle at least one side
- never leave correct answers in obvious positional order
- verify answer N is not automatically option N across the whole set

If adapting an assessment matching task, preserve the concept but scramble the presentation
so students must actually reason.

SECTION 1.1 GOLD-STANDARD INTERPRETATION
================================================================

The approved Physics Section 1.1 test established these decisions:

1. DASHBOARD NAMING WINS.
   The correct folder is u1_1_practice_sets/, not practice_sets_1_1/.
   The correct ZIP is u1_1_practice_sets.zip.

2. THE FIVE HTML FILENAMES ARE LOCKED.
   practice_set_1_1.html
   practice_set_1_1_2.html
   practice_set_1_1_3.html
   extra_practice_1_1.html
   cyu_1_1.html

3. PHYSICS PRACTICE USES A 31-FAMILY POOL.
   12 DOK 1, 12 DOK 2, 5 DOK 3, 2 DOK 4.
   These families can be rearranged/reworded across the four 16-problem practice files.

4. THE ENDLESS-PAGE ALGEBRA ARCHITECTURE IS GOOD.
   Use class="problem" only.
   No .ps-page wrappers.
   No problem half.
   Keep the approved practice_set.css approach.

5. GRAPHS AND DIAGRAMS ARE TWO DIFFERENT VISUAL CATEGORIES.
   Graphs are produced with graph_tool.py / generate_graphs.py.
   Physics diagrams are static model/schematic PNGs.

6. DEFAULT VISUAL TARGET = AT LEAST 5 GRAPHS + 5 DIAGRAMS PER SECTION PACKAGE.
   The Section 1.1 revision intentionally contained five of each.

7. DO NOT FORCE NON-GRAPH PHYSICS MODELS THROUGH GRAPH_TOOL.
   Force diagrams, motion dots, hanging objects, flawed models, circuits, rays, field lines,
   and similar schematics should be made as proper static Physics diagrams.

8. GRAPH PNGs AND DIAGRAM PNGs HAVE DIFFERENT DELIVERY BEHAVIOR.
   Graph-tool PNGs are generated during QA, verified, then removed before ZIP.
   Static diagram PNGs remain packaged in figures/.

9. A FUTURE-CONTENT DIAGRAM CAN BE USED ONLY AS A GENERIC MODEL WHEN THE QUESTION DOES NOT
   REQUIRE FUTURE PHYSICS KNOWLEDGE.
   For example, a force-arrow picture can serve as an example of a scientific model in
   Section 1.1 without asking students to calculate net force before that content is taught.

10. SOURCE ADAPTATION IS ALLOWED.
    Physics practice questions may be reworded/rearranged from the assessment plan,
    formatives, and summative while preserving concept and DOK. Practice sets should not be
    verbatim clones of graded assessments.

11. STATIC DIAGRAMS SHOULD LOOK LIKE CLASSROOM PHYSICS FIGURES.
    Simple objects, clear arrows, readable labels, neutral titles, and enough white space.
    The uploaded force-diagram examples are the visual reference style.

12. FINAL DELIVERY IS THE ZIP + QA LOG.
    Do not deliver only loose HTML files.
